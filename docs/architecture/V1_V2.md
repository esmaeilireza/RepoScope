# RepoScope Architecture - V1 (shipped) and V2 (roadmap)

**Status as of 2026-10-23:** V1 is complete and verified end-to-end. V2 items
have not started. No external claim should reference V2 as shipped.

## V1 - what is actually running

### Three audit gates
- `dataops` - 22 rules (dbt, schemas, lockfiles, data-leak, migrations)
- `iiot`    - 10 rules (Modbus, PLC config, LOTO, network topology, mocks)
- `webapp`  -  2 rules + 9 legacy `general-*` hygiene checks

Total: 34 spec rules across three gates. Excludes `cross.yaml` (2) and
`general.yaml` (14), archived in `docs/specs/_archive/` during Phase 0.

### Router - `scripts/route_repo.py`
Deterministic file-signal classifier. Reads `package.json`, `next.config.*`,
`dbt_project.yml`, `requirements.txt`, `pyproject.toml`, `*.st/*.scl/*.lad`, and
library names in dependency manifests. Returns `{profiles, evidence}`.
CLI prints `[ROUTE] profiles: ...` and `[ROUTE] <profile> evidence: ...`.

### Industrial-ML filter - `scripts/industrial_ml_filter.py`
Detects realtime / edge / time-series / MLOps signals in dependency manifests
and maps them to `docs/notes/industrial-ml/` categories. When any signal
matches, prints `[IML] <category>: signals=... | notes=...`. Deterministic.

### Neo4j property graph
- **Server:** Neo4j 5 Community (local install; see README for setup) (Windows service
  `neo4j`). Start/stop via `pnpm neo4j:up` / `pnpm neo4j:down` / `pnpm neo4j:status`.
- **Schema:** `scripts/kg/schema.cypher` - uniqueness constraints on Rule.id,
  Concept.name, Book.title, Profile.name.
- **Seed:** `scripts/kg/seed.py` - reads `public/knowledge/specs.json` and
  writes `(:Rule)`, `(:Concept)`, `(:Book)`, `(:Profile)` nodes with
  `BELONGS_TO`, `GROUNDED_IN`, `CITED_IN` edges.
- **Ground query:** `scripts/kg/ground.py <rule-id>` runs
  `MATCH (r:Rule {id:$id})-[:GROUNDED_IN]->(c:Concept)-[:CITED_IN]->(b:Book)`
  and returns the citation chain.
- Every finding in the CLI (except legacy `general-*`) prints:
  `   Grounded in: <book title> - concept: <concept name>`

### Citation gate - `lib/knowledge/citation-gate.ts`
Strips `page N`, `section X.Y`, and `According to <Name>` forms from LLM
output unless the sentence also cites a registered book title. Verified by
5 tests in `__tests__/llm-layer.test.ts`.

### CI gates (all green)
- `pnpm typecheck` - TypeScript compiles
- `pnpm test` - Jest, 25 tests passed
- `pnpm build` - Next.js production build
- `pnpm reposcope --repo . --strict` - self-audit
- GitHub Actions `.github/workflows/ci.yml` runs all of the above

## V2 - roadmap, not yet built

- **AST ingestion:** parse Python/TypeScript into `(:AST_Node)` nodes linked
  to `(:Rule)` via `VIOLATES`. Currently regex-based detection only.
- **`general-*` migration:** promote 9 hygiene checks in `lib/audit.ts` to
  `docs/specs/webapp.yaml` with proper `references:` blocks and Neo4j grounding.
- **`dataops-004` rename:** `lib/dataops-audit.ts` still emits `dataops-004`
  for the data-leak check (original rule was archived). Rename for clarity.
- **Router consumes IML signals:** currently orthogonal. `route_repo.py`
  classifies by file signals; `industrial_ml_filter.py` flags ML context but
  does not feed back into routing. A repo with `mlflow` + `prophet` +
  `pymodbus` routes as `iiot` only. V2 merges IML categories into the profile
  set (`03-time-series -> dataops`, `02-iiot-edge -> iiot`).
- **PLC register extraction:** for IIoT repos, extract register maps from
  code and link them as `(:PLCRegister)` nodes.
- **Multi-agent pipeline:** planner / auditor / reviewer agents per
  Agentic GraphRAG. Currently single-pass deterministic.
- **Citation-gate edge cases:** gate misses oblique forms ("Smithfield
  argues...") and lowercase names ("according to smithfield"). V2 extension.
- **Industrial-ML drift detection:** wire `outlier-analysis.md` into the
  time-series category as a runtime check.

### Why `webapp-demo` scores 0/100

`pnpm reposcope --repo demo-repos/webapp-demo --strict` produces 11
findings: 2 grounded (`webapp-001`, `webapp-002`) + 9 ungrounded
`general-*` hygiene rules (`general-docs-001`, `general-legal-001`,
`general-cicd-001`, `general-quality-001`, `general-security-001`,
`general-deps-001`, `general-docs-002`, `general-docs-003`,
`general-config-001`).

The 0/100 score reflects the state of an empty Next.js skeleton (no
README, LICENSE, CI, tests, or security documentation), not a defect in
the tool. The `general-*` rules are V2-track (see "`general-*` migration"
above) and have no Neo4j node yet, so they do not print a grounding line.
Fixing the two `webapp-*` findings would raise the score; the nine
`general-*` rules will remain ungrounded until the V2 migration ships.

## Known gaps for the reviewer

Every item in V2 above is a gap. The single most important one:
**regex detection is not AST detection.** A rule fires when a string pattern
matches a file; the rule does not parse the code into a syntax tree. This is
adequate for the deterministic checks shipped (secret scan, lockfile presence,
LOTO docs, PLC IP literal) and not adequate for semantic checks (data flow,
schema compatibility, idempotency). The self-audit and demo outputs are
honest about this in `pnpm reposcope`'s output format: it shows *what file
matched*, not *what the code does*.
