# RepoScope Knowledge Index

> Human-readable index of source-grounded audit rules, knowledge concepts, and GraphRAG artifacts.
>
> Runtime artifacts:
>
> - `public/knowledge/specs.json`
> - `public/knowledge/graph.json`
>
> Neo4j is used only as an **offline authoring/validation workbench**.
> RepoScope runtime remains static and portable through `graph.json`.

---

## 1. IP boundary and attribution policy

RepoScope treats source material ethically and transparently.

This repository does **not** reproduce:

- copyrighted book text;
- long verbatim excerpts;
- diagrams;
- exercises;
- case studies;
- private author correspondence unless explicitly permitted.

RepoScope stores only:

- source metadata;
- short paraphrased concepts;
- deterministic repository-audit checks;
- derived architectural heuristics;
- property-graph schemas;
- citation metadata.

Every source-derived rule must preserve this chain:

```text
finding -> rule ID -> YAML spec -> graph node -> concept -> source
```

Preferred attribution format:

> Grounded in: `[Book/Standard Title]`, `[Author/Standards Body]`.  
> RepoScope rule: `[rule-id]`.  
> This is a derived operational heuristic only. No verbatim source text is reproduced.

Page, chapter, or section references are included only when verified by the source note.

If a precise location cannot be verified, this index uses:

```text
Not established by these sources
```

Author outreach status is **not** approval. Rules marked `contacted` may be published only as derived heuristics with prominent attribution unless the author objects or provides a preferred citation format.

## 7. Neo4j offline validation contract

Neo4j is used only as a local graph workbench.

The expected workflow is:

```text
Markdown notes / PDF-derived concepts
        ↓
human review
        ↓
YAML specs
        ↓
scripts/build_knowledge.py
        ↓
scripts/kg/assemble_graph.py
        ↓
public/knowledge/graph.json
        ↓
local Neo4j import
        ↓
Neo4j validation
        ↓
export back to graph.json
        ↓
RepoScope runtime uses static graph.json
```

The Neo4j graph must satisfy these invariants:

| Check | Expected Result |
|---|---|
| Every `Rule` node has a stable `id` | `rule:<rule-id>` |
| Every `Rule` node has a `rule_id` property | must match YAML `id` |
| No duplicate `rule_id` values | zero duplicates |
| Every published rule has at least one grounding edge | `GROUNDED_IN` or `CITED_IN` |
| Every concept has at least one source edge | `SUPPORTED_BY` or `CITED_IN` |
| Every source has attribution status | not empty |
| No rule rationale contains unverified page/section/chapter claims without a source edge | zero suspicious ungrounded citations |
| Graph RAG candidate rules are not treated as published until YAML exists | candidate status enforced |

Suggested local commands:

```powershell
python scripts/build_knowledge.py
python scripts/kg/assemble_graph.py
python scripts/kg/validate_graph.py

$env:NEO4J_URI="bolt://localhost:7687"
$env:NEO4J_USER="neo4j"
$env:NEO4J_PASSWORD="change-this-password-now"

python scripts/kg/neo4j_import.py
python scripts/kg/neo4j_validate.py
python scripts/kg/neo4j_export.py

pnpm test
pnpm audit:self
pnpm build
```

## 8. Graph RAG folder prompt policy

The source folder should be named:

```text
Graph RAG
```

not:

```text
Grapgh Rag
```

Each book/source in that folder should produce original Markdown notes using this rule:

```text
Create an original, concise Markdown knowledge document from the supplied sources.
Do not reproduce the book or provide long verbatim excerpts.
Paraphrase only.
Do not invent details.
Clearly distinguish:
1. source-backed facts,
2. RepoScope synthesis,
3. items not established by these sources.
```

Every important claim must include the most precise available citation:

```text
Book title, author, chapter/section/page if verified.
```

If not verified:

```text
Not established by these sources.
```

Candidate Graph RAG rule IDs must follow:

```text
graph-001
graph-schema-001
graph-retrieval-001
graph-grounding-001
```

Do not invent the meaning of an existing rule ID.

If a rule ID is supplied but not established by the sources, mark it:

```text
meaning to be confirmed
```

## 9. Repository-audit check policy

RepoScope rules must be deterministic repository checks whenever possible.

A valid rule should specify:

- repository evidence to inspect;
- file glob or path pattern;
- pass condition;
- fail condition;
- severity;
- fix;
- source citation.

Examples of acceptable evidence:

```text
files
tests
CI configuration
lockfiles
schemas
manifests
Markdown docs
YAML specs
graph.json nodes
TypeScript emitted rule IDs
```

Examples of unacceptable evidence:

```text
operational advice that cannot be checked from repository files
vague architectural opinion without a deterministic test
copied book text
fabricated page citations
author approval assumed but not received
```

## 11. Unverified or not established items

The following must not be treated as verified:

1. Author preferred citation formats are pending replies.
2. Exact page numbers for concepts are not stored unless verified.
3. `Agentic GraphRAG` concepts are candidate grounding sources until reviewed against the actual source notes.
4. `Data Management at Scale` governance rules are registry-only until YAML rules are created.
5. `OPC Unified Architecture` rules are registry-only until deterministic repository checks are defined.
6. Concept counts are not listed because they depend on extraction output and should be generated by `scripts/kg/assemble_graph.py`.
7. Graph RAG rules are not active findings until they pass the YAML/spec/test contract.

## 12. Maintenance rules

When adding a new source:

1. Add it to `lib/knowledge/books.ts` only if it is actually used.
2. Add a source node to the graph through extraction or manual curation.
3. Add only paraphrased concepts.
4. Add citation metadata.
5. Mark unverified locations as:

```text
Not established by these sources
```

When adding a new rule:

1. Add it to the correct `docs/specs/*.yaml`.
2. Ensure the rule ID matches the TypeScript emitter exactly.
3. Regenerate:

```powershell
python scripts/build_knowledge.py
python scripts/kg/assemble_graph.py
python scripts/kg/validate_graph.py
```

4. Optionally validate in local Neo4j:

```powershell
python scripts/kg/neo4j_import.py
python scripts/kg/neo4j_validate.py
python scripts/kg/neo4j_export.py
```

5. Run:

```powershell
pnpm test
pnpm audit:self
pnpm build
```

Critical invariant:

```text
TypeScript finding.ruleId
  == YAML docs/specs/*.yaml rule.id
  == public/knowledge/specs.json rule.id
  == public/knowledge/graph.json rule:<rule-id>
```

If this chain breaks, grounding silently fails.
